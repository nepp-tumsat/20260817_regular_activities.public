  3. 説明が終わったらチームでアイデアを決める。この間に各自 Step 2〜3(キー設定と疎通確認)を済ませる

詰まったら手を挙げてくださいセットアップで詰まったまま黙っていると、開発時間まで持ち越して一番損をします。アイデアの説明中でも構わないので、動かない時点ですぐ運営に声をかけてください。

STEP 1 — ペルソナ:「大学生」ではなく「田中さん」にする

「大学生向けのアプリ」だと、何を作っても正解に見えて、結局なにも決まりません。実在しそうな1人まで絞ると、機能を入れるか外すかがその場で決められます。

時間割

お金

性格
人に聞くのが少し面倒。スマホは常に見ている

「席を探して歩き回るくらいなら、もう購買でいいかなってなる」

今日のペルソナは「自分」か「隣の人」でいい本来はインタビューして作りますが、今日は55分しかありません。チームの誰かが実際に困っていることを題材にするのが一番速く、しかも精度が高いです。

STEP 2 — 課題の具体化:「不便」で止めない

課題がぼんやりしていると、解決策もぼんやりします。いつ・どこで・何回・どうなるかまで書けたら、解くべきものは自動的に見えてきます。

✗ ぼんやり 学食が混んでいて不便
✓ 具体的 田中さんは12:15に学食へ着くが席がなく、5〜10分探し回る。見つからないと購買のパンを買って教室で食べることになり、週に2〜3回そうなっている。

左は「で、何を作る?」に答えられません。右は「着く前に空席が分かればいい」がすぐ出てきます。

STEP 3 — 市場調査:5分だけ「もう誰かが解いてないか」を調べる

既にあるものを作り直すのも学びとしてはアリですが、「なぜ既存では足りないのか」を1行で言えると、作るものが一気にシャープになります。

今ある手段できること足りないこと
大学の公式サイトメニューと営業時間が分かる混雑状況は載っていない
Google Maps の混雑度建物単位のざっくりした混み具合席が空いているかは分からない。反映が遅い
友達に LINE で聞く正確相手が返信するまで分からない

この表から、空いているところが1行で書けます。

結論(=作る理由)リアルタイムに・席単位で・誰にも聞かずに分かる手段が存在しない。
5分ルール検索して3つ見たら終わりにしてください。市場調査は無限にできてしまい、「調べていたら開発時間がなくなった」が今日いちばん多い失敗です。深掘りは動くものができた後で。

STEP 4 — MVP:その課題が解ける最小の形に削る

MVP(Minimum Viable Product)= 最小限だけど、ちゃんと価値が出る形。 パーツを順番に作っていくと最後まで誰も使えませんが、MVPから育てると最初から使えます。

✗ パーツから作る 🛞タイヤ → 🔩車体 → 🚗完成 完成するまで誰も移動できない。時間切れ = 何も残らない
✓ MVPから育てる 🛹スケボー → 🛴キックボード → 🚲自転車 → 🚗車 どの段階でも「移動できる」。時間切れでも成果が残り、途中で改善もできる

セットアップ

チームに配られたAPIキーで Claude Code を使えるようにします。所要5分。Step 1 のインストールは時間がかかるので、先に走らせてからアイデアの話を聞いてください。

個人で Claude Pro / Max を契約済みの人へ普段の自分のログインのまま参加してOKです。この手順は不要なので、アイデアの出し方へ進んでください。
作業環境macOS のターミナル、または Windows の WSL(Ubuntu など)で作業します。Windows の人は PowerShell やコマンドプロンプトではなく WSL のターミナルを開いてください。WSL がまだ入っていない人は導入に時間がかかるので、運営に声をかけてください。

  1. Claude Code をインストールする

    すでに入っている人は飛ばしてください(claude --version で確認できます)。

    curl -fsSL https://claude.ai/install.sh | bash

    WSL で curl: command not found と出たら、先に curl を入れてから再実行してください。

    sudo apt update && sudo apt install -y curl

  2. チームのAPIキーを環境変数にセットする

    チームリーダーから受け取ったキー(sk-ant-api03-…)を貼り付けます。

    export ANTHROPIC_API_KEY="sk-ant-api03-..."

    ターミナルを開き直すと消えるので、その場合はもう一度実行してください。

  3. 起動して初期設定をする

    mkdir hands-on && cd hands-on
claude
    1. 「このAPIキーを使用するか」と聞かれたら Yes を選ぶ
    2. /model と入力して Sonnet を選択(今日はSonnetで進めます)
    3. 疎通確認として軽い指示を1回:「このフォルダに hello.txt を作って」

    hello.txt ができたらセットアップ完了です 🎉

  • スクリーンショット・配信画面に写さない
  • チーム外に共有しない
  • キーはイベント終了時に失効します。持ち帰っても使えません。
  • 途中で応答が返ってこなくなったら、運営に声をかけてください。

チーム開発でコンフリクトしない作法

4人で同じリポジトリを触ると、必ず「他の人の変更と衝突した」が起きます。開発時間は55分しかないので、衝突を上手に直す方法ではなく、そもそも衝突しない配置にする方法をまとめます。

1. 2人1組 × 2台で、担当は「機能」で切る

1人が Claude Code に指示を出し、もう1人が結果を見て次の指示を考える。初めてなら4人バラバラより速く、学びも大きいです。

担当は機能で分けます。「HTML担当・CSS担当」のようなレイヤーでは分けません。

✗ レイヤーで分ける✓ 機能で分ける
ペアA: HTML
ペアB: CSS + JS		ペアA: 投稿ボタン(HTML+CSS+JS 全部)
ペアB: 一覧表示(HTML+CSS+JS 全部)

レイヤーで分けると、HTMLができるまでCSSが書けず、お互いの完成待ちになります。機能で分ければ、それぞれが最後まで動くものを作れます。Claude Code も「投稿ボタンを作って」の1発でHTML/CSS/JSを横断して書いてくれるので、そのほうが自然です。

2. 最初の5分は1人だけが動く

空のリポジトリに全員が同時に push すると即事故ります。

  1. 1人が雛形を作って push — 機能ごとにファイルを分けておくのがポイント
  2. index.html に機能ごとの差し込み口を先に確定させる — これで以降 index.html を誰も触らずに済みます
  3. 全員が clone してから分担開始
index.html                         ← 器。差し込み口を置いたら以降さわらない
features/post.js   + post.css      ← ペアA
features/list.js   + list.css      ← ペアB
<div id="post"></div>
<div id="list"></div>

各ペアは自分のJSからこの差し込み口に描画するだけになります。

3. Claude Code に担当外を触らせない

ここが今日いちばん効くポイントClaude Code は放っておくと関係ないファイルまで整形・リファクタします。つまりAIが勝手に他の人の担当ファイルを書き換えてコンフリクトを作ります。

毎回、触ってよいファイルを明示してください。

features/post.js と post.css だけを変更してください。
他のファイルは読んでも構いませんが、編集はしないでください。

1回の指示は小さく。 大きな指示で複数ファイルを一気に書き換えさせるほど、衝突する面積が広がります。

チームの約束は CLAUDE.md に書く。 リポジトリ直下に置くと、チーム全員の Claude Code が同じ前提で動きます。

# チームの約束
- 担当: ペアA=features/post.* / ペアB=features/list.*
- 担当外のファイルは編集しない
- index.html は変更しない(差し込み口は確定済み)
- CSSのクラス名は機能名をプレフィックスにする(post-btn など)

4. 小さく、頻繁に

15分に1回は push。溜めるほど解決が大変になります。

git pull --rebase              # 作業を始める前に必ず
# ...作業...
git add -A && git commit -m "投稿ボタンを追加"
git push

5. 詰まったら「直す」より「やり直す」

時間が限られているので、解決に5分かかりそうなコンフリクトは潔く捨てます。

git merge --abort                  # とりあえず元に戻す
git checkout --theirs index.html   # 相手の版を採用

そのうえで自分の変更内容を Claude Code にもう一度やらせる。手で直すより速いです。

まとめ
  • 組み方 — 2人1組 × 2台。担当は「機能」で切る(HTML担当・CSS担当にしない)
  • 最初の5分 — 1人が雛形を push → index.html に差し込み口を確定 → 全員 clone
  • Claude Code — 「このファイルだけ変更して。他は編集しないで」を毎回言う。指示は小さく。約束は CLAUDE.md に書く
  • 動かし方 — 作業前に git pull --rebase、15分に1回 push
  • 詰まったら — 5分で直らないコンフリクトは捨てて、Claude Code にやり直させる
